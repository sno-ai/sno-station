# Finish：你不在，活也会干完

你把任务交给 agent，然后离开。Finish 负责到点把 agent 叫回来，盯着长任务跑完，
干不成的时候把原因直接告诉你。

| 你想要 | 会发生什么 | 例子 |
| --- | --- | --- |
| **Timed tasks（定时任务）** | 到了你说的时间，一个 agent 启动并把事做了。可以一次、每天或每周。 | “明天早上 9 点检查一下夜间构建。” |
| **盯着长任务** | agent 每隔一段时间看一次，直到任务结束，然后回报。 | “每十分钟看一次训练，跑完告诉我。” |
| **额度用完也不停** | 另一个 agent 从上一个停下的地方接着干。 | “这个要跑一整晚，用 `rotate-agent`。” |

## 一句话开始

在 Claude Code 或 Codex 的对话里，把任务和时间一起说：

```text
明天早上 9 点检查夜间构建，告诉我哪些失败了。
```

要重复做的事：

```text
每天早上 7 点写一份日报。
```

agent 会把时间记在这项任务的笔记旁边。你可以关掉对话，也可以关掉终端。
到了时间，一个 agent 会启动，做你交代的事。

`sno setup` 会装一个小服务，每分钟看一次时间。它用你自己的用户账号运行，
支持 Linux 和 macOS。macOS 上需要 Homebrew 的 `bash`、`coreutils`、`flock` 和 `jq`。

## 查看已安排的任务

```sh
sno heartbeat --due
```

它列出每项任务、下一次的时间（按你本地时区）、是否重复，以及上一次的结果。

只看没按计划完成的：

```sh
sno heartbeat --due --problems
```

下次你开始对话时，agent 也会看到同一份清单，所以错过的任务不用你问就会告诉你。

要取消一项任务，从清单里那一行的开头复制记录文件的路径：

```sh
sno heartbeat --due-cancel <记录文件路径> "写一份日报"
```

不写任务内容，就取消这份记录里的全部定时任务。

## 到点时会发生什么

- **对话还开着。** 由这段对话的一个副本去做。你正在输入的那段对话保持原样。
- **对话已关闭。** 接着那段对话继续，它原来知道的都还在。
- **对话已不存在。** 用这项任务保存下来的笔记开一段新对话。

重复的任务在夏令时切换前后保持同一个钟点。错过了好几天，任务会在能跑的时候
跑一次，然后排到下一个时间。它不会把错过的每一天都补跑一遍。

每次运行都以三种回答之一结束：做完了；没做完和原因；等你处理和需要你做什么。

## 跑不起来的时候

没能启动的任务保持待办。原因会用平常的话写在旁边，例如登录过期或额度用完。
下一次检查时会再试。没有启动的任务不会被标成完成。

定时运行使用 agent 自己的设置，不会多给任何权限。如果这件事需要某项你还没给的
权限，请在离开前先允许。

## 长任务和额度

要跑几个小时的任务，让 agent 盯着：

```text
每十分钟看一次构建，跑完告诉我。
```

可能超出一个 agent 额度的工作，告诉正在干活的 agent 使用 `rotate-agent`。
快到上限时它会写好交接说明，叫醒另一个 agent，从同一个提交继续。
主 [README](../README.md) 里有一个真实发生的晚上，出过的错也原样留着。

## 目前的边界

- 定时任务会启动 Claude Code 和 Codex。Cursor、Hermes Agent 和 OpenClaw 还不能这样启动。
- 电脑必须开着并且没有休眠。休眠中的笔记本要等醒来后才会启动任务。
- 在 Linux 上，服务在你登录期间运行。想在退出登录后继续运行，执行一次
  `sudo loginctl enable-linger $USER`。需要这样做时 `sno setup` 会提示你。
- 每分钟检查一次时间，所以任务会在设定时间后约一分钟内启动。
- 对话关闭、服务重启之后任务都还在。整台电脑重启的情况还没有做过真实测试。
- 启动了不等于做完了。请看这次运行是怎么结束的。

## 给 agent

一项定时任务是任务进度记录里 `## Due` 下的一条。使用 `sno heartbeat --due-set`、
`--due-cancel` 和 `--due`。记录格式、结果行和全部规则见
[Heartbeat 说明](../apps/heartbeat/README.md)。
