# Sno Station：あなたの AI エージェントが、ひとつのチームで働く。

**Sno Station では、AI コーディングエージェントがひとつのチームとして働きます。** 新しいエージェントでも、新しいモデルでもありません。いま使っている Claude Code、Codex、Cursor をそのまま動かします。

まずは、普段なら付きっきりで見ている仕事から始めてください。片方が作り、もう片方がレビューします。指摘は結果があなたに届く前にふたりで片づけます。片方が利用上限に当たれば、もう片方がタスクを引き継ぎます。今日あなたが直したことは、明日にはエージェントのルールになります。

**タブを閉じても、エージェントは動きます。** Anthropic の William Hu が、[常時稼働するエージェントの仕組み](https://claude.com/resources/articles/building-always-on-agents)を説明しています。何かに起こされるまで眠り、作業して、何が起きたかを保存し、また眠ります。Sno Station を入れると、ベンダーの違うエージェントがこの流れで動きます。メモリはひとつです。それぞれのターンが終わると受信箱を読みます。チャットを閉じていても、指定した時刻にタスクが始まります（いまは Claude Code と Codex）。エージェントがあなたを必要とするとき、通知は一度だけ届きます。

## Station：お互いに確認し、片方が止まればもう片方が引き継ぐ

これを作る前に、私たちに起きた 3 つのことです。

- エージェントが、聞く必要のなかった質問をするために止まりました。7 時間後に戻ると、何ひとつ進んでいませんでした。
- エージェントが細かい質問を 15 個よこしました。30 分後、どれもエージェントが自分で答えられるとわかりました。
- あるエージェントが真夜中に別のエージェントを起こそうとして、起こせませんでした。どちらも朝までそのままでした。

エージェントは速い。遅いのは待ち時間です。あなたを待つ。利用上限のリセットを待つ。誰かが結果を次のウィンドウへ運ぶのを待つ。

> **ひとつのエージェントが止まっても、仕事は止まらない。**

それにはエージェントが 2 つ以上必要です。違うベンダーのエージェントを組み合わせるのがいちばんうまくいきます。自分の作業をレビューするエージェントは、作業したときと同じ癖を持ち込みます。サブスクリプションが 1 つだけなら、使い切ればそこで終わりです。

だから、以下のどの機能でも、もうひとつのエージェントが働きます。

| 機能 | もうひとつのエージェントがすること |
| --- | --- |
| [**Mem**](#mem) | 片方がメモリの変更を提案します。別のベンダーのエージェントが接続されていれば、そのエージェントが確認します。 |
| [**Reach**](#reach) | エージェント同士でタスクや返事を渡します。あなたが間に入る必要はありません。 |
| [**Finish**](#finish) | 片方のクォータが残り少なくなると、別のエージェントが同じコミットから続けます。 |
| [**Learn**](#learn) | ひとつのエージェントのミスが、あなたの承認を受けて全員のルールになります。 |

**いま別の意見を聞きたいですか？** どちらかのエージェントにこう伝えます。

```text
peer-review this
```

レビュアーは、その会話を一度も見ていない新しいセッションで動きます。エージェントが 2 種類あれば、必ず別のエージェントです。レビューが毎回問題を見つけるわけではありません。それでも、書いた本人には見えなかった問題を見つけ続けます。[`peer-review` の仕組み →](https://github.com/sno-ai/sno-station-skills/tree/main/skills/J-peer-review-and-audit/peer-review)

**いまスターを付けておいてください。次に午前 2 時にエージェントが止まったとき、これがどこにあったか知りたくなります。**

<a id="mem"></a>

## Mem：ひとつのエージェントに一度伝えれば、全員に伝わる

> すべてのエージェントが、ひとつのメモリを共有します。毎晩整理され、聞く前に必要なことが届きます。

### できること

| | |
| --- | --- |
| **すべてのエージェントにひとつのメモリ** | 今日 Claude Code に伝えたことを、明日には Codex と Cursor も知っています。プロジェクトの説明は一度で済みます。 |
| **仕事に必要なことだけ** | あなたのルール、決めたこととその理由、時間がたっても変わらないプロジェクトの情報、まだ守られていない約束です。「テストを実行した」といった報告や、ひとつのタスクに限った制約は残しません。 |
| **どのプロジェクトにも持っていけるルール** | 「どこでも中国語で答えて」と言えば、どのプロジェクトにもそのルールがついてきます。ひとつのプロジェクトに限ったルールや、Sno が適用範囲を判断できないルールは、そのプロジェクトに残ります。 |
| **毎晩整理する** | 重複はまとめます。新しい事実に置き換わった古い事実は退けます。最初の削除の前に、すべてをバックアップします。 |
| **聞く前に届く** | セッションの最初に届くのは、確認済みの短いリストです。メモリ全部が届くわけではありません。「マージして」と入力すると、メッセージと一緒にあなたのマージのルールが届きます。無関係なメッセージには何も添えません。 |
| **別の目で確認する** | メモリを置き換えるには再確認が必要です。別のベンダーのエージェントを接続していればそこに確認を頼み、いなければ別の呼び出しで確認します。 |

### 実際の動き

実際のエージェントで試したことを 2 つ紹介します。

```text
we told Codex:   the service moved from port 8070 to 8090
the memory:      old fact retired, new fact kept
later, we asked: which port?
Claude Code:     8090
Codex:           8090
```

```text
we told Claude Code the same rule twice, in different words
the memory:      one entry
```

エージェントのメモリには、気づきにくい落とし穴が 2 つあります。残るべきことを忘れ、忘れるべきことを覚え続けます。高くつくのは後者です。変更前の締め切りをまだ「覚えて」いるエージェントは、自信満々でそのとおりに動いてしまいます。だからこのメモリは、わざと忘れます。

公開されているメモリのテストでの結果は、すべての回答とトレースとともに [`evals/`](../../evals/) にあります。

### 使い方

実行するものはありません。インストールすれば有効です。

上で説明した整理と確認には、REM Enhanced か Agent Native が必要です。Local First はモデルを呼びません。あなたの言葉をそのまま保存し、記憶が 2 件食い違えば両方を残します。

覚えてほしいことがあれば、こう伝えます。

```text
Remember that we never deploy on Fridays.
```

記憶が間違っていたら、それも伝えてください。エージェントが訂正を保存し、古い記憶を退けます。

エージェントのメモリが正常か確かめるには、次を実行します。

```bash
sno memory doctor --harness claude
```

`CLAUDE.md` や `AGENTS.md` にすでに書いてある行は、繰り返し表示しません。記憶がどちらかのファイルと食い違う場合は、ファイルが優先です。

**まだできないこと：** Hermes Agent と OpenClaw で、上で説明した整理と確認を試したのは、プラグインのテストだけです。

エージェントごとのガイド：[Claude Code](../mem-claude/usage-guide.md) · [Codex](../mem-codex/usage-guide.md) · [Cursor](../mem-cursor/usage-guide.md) · [Hermes](../mem-hermes/usage-guide.md) · [OpenClaw](../mem-claw/usage-guide.md)

## Reach：私はエージェント同士の伝言を運ばなくなった

> エージェント同士が直接話します。あなたは伝言を運ばなくて済みます。

エージェントを 5 つ動かすというのは、以前はターミナルが 5 つあり、その真ん中で私たちが片方の言ったことをもう片方へ運ぶ、ということでした。その役目は終わりです。

### できること

| | |
| --- | --- |
| **Instant Messenger** | エージェントが今すぐ答えを必要とするときに使います。Reach が別のエージェントに連絡し、返答を待ちます。 |
| **Agent Email** | エージェントがメッセージやタスクを残します。先に保存するので、相手は後から処理して返信できます。 |
| **ひとつのタスクに 2 つのエージェント** | 片方が作り、もう片方ができたものに物申します。指摘は結果があなたに届く前にふたりで片づけます。 |
| **話しかける相手は 1 つだけ** | 参謀役がプロジェクトごとにリードのエージェントを立てます。あなたに戻ってくるのは、あなたの判断が要るものだけです。 |
| **必要なときに一度だけ通知** | 質問、結果、承認は、最後に入力したマシンに一度だけ届きます。 |
| **コンピューターをまたいで使える** | ノートパソコンのエージェントからデスクトップのエージェントに質問できます。同じ LAN か Tailscale を使います。中央サーバーはありません。 |

### 実際の動き

エージェントがあなたを待っているときのステータスラインです。

```text
[sno] 2 agents are waiting for you
  Claude in web-app needs your approval (Bash) · 1m
  Codex in api asks: Should the billing migration run tonight? · 5m
```

`sno squad` なら、チーム全体をひとつの画面で見られます。

```text
Sno Station · squad · 09:15 · 2 need you · 2 working · 2 finished
Waiting for you (2)
  Claude in web-app needs your approval (Bash) · 1m
  Codex in api asks: Should the billing migration run tonight? · 5m
Needs you (2)
> claude web-app       approve a permission · Fix the login redirect loop …   1m
  codex api            asked a question · Migrate the billing tables to th…   5m
Working (2)
  claude docs-site     Rewrite the quick-start page for the 2.0 install      12s
  codex api            Review the rate limiter change from the web-app age…  40s
Finished (2)
  cursor infra         finished · result unseen · Rotate the staging certi…  25m
  claude web-app       finished · Bump the UI kit to 4.2                      2h
```

### 使い方

**仕事を送る。** エージェントに一言伝えます。

```text
Send this task to the reviewer and tell me when it is done.
```

エージェントが作業中に届いたメールは、そのターンが終わると読まれます。複数のエージェントに送ったタスクを引き受けるのは、そのうちの 1 つです。あなたがそのウィンドウで入力中でも、書きかけの下書きはそのまま残ります。

<a id="new-in-20-tag-team"></a>

**ひとつのタスクを 2 つのエージェントに任せる。**

```bash
sno reach pair "Fix the login redirect"
```

どちらも tmux のウィンドウで動くので、開いて様子を見られます。種類の違うエージェント 2 つにサインインしていれば、それぞれ 1 つずつ付きます。1 つだけでも、別々の 2 つのセッションでペアを組み、レビューが同じ系統の中にとどまったことをコマンドが伝えます。

**話しかける相手を 1 つにする。** Claude Code では `/cos`、Codex では `$cos` と伝えます。そのエージェントがあなたの参謀役になります。仕切る側もチェックを受けます。夜のシフトのあと、参謀役はプロジェクトリードが自分で自分に出した承認を見直します。従う指示はすべて [sno-station-skills](https://github.com/sno-ai/sno-station-skills/tree/main/skills/T-delegation-and-work-orders) にあります。

**誰があなたを待っているか見る。**

```bash
sno squad
```

いま、どのエージェントで何が動くか。

| | Claude Code | Codex | Cursor | Hermes | OpenClaw |
| --- | --- | --- | --- | --- | --- |
| ターン終了時にメールを受け取る | 対応 | 対応 | 対応 | 未対応 | 未対応 |
| 送信箱、ひとつのエージェントだけが引き受ける仕組み、エージェントの呼び起こし、通知 | 対応 | 対応 | 対応 | 対応 | 対応 |
| 承認依頼の通知 | 対応 | 対応 | 未対応 | 未対応 | 未対応 |

**まだできないこと：** ステータスラインは Claude Code と Cursor で使えます。デスクトップ環境がないマシンでは、通知は `sno squad` にだけ表示されます。2 台のコンピューターで使うには、両方に Reach を入れ、連絡先を交換する必要があります。`sno reach --help` で `network` と `peer` を確認してください。

## Finish：私は寝た。仕事は続いた。

> 片方のエージェントが利用上限に達しても、もう片方が同じコミットから続けます。

### できること

| | |
| --- | --- |
| **指定した時刻に作業する** | タスクと時刻を伝えて、席を離れます。その時刻になると、会話が開いていても閉じていてもエージェントが起動します。1 回だけ、毎日、毎週のいずれかです。 |
| **利用上限に当たっても作業は止まらない** | クォータが尽きる前に、作業中のエージェントが引き継ぎメモを書いて別のエージェントを起こします。そのエージェントが同じコミットから続けます。 |
| **長い実行を最後まで見守る** | 終わるまで、エージェントが数分おきに確認します。 |
| **「終わりました」は何の証拠にもならない** | タスクには合否を判定するチェックがあります。ひとつひとつ、実際に動かして確かめます。 |
| **ウィンドウを閉じても終わらない** | 会話を開き直すと、タスクのメモも戻ります。時刻を指定したタスクはその会話で続きます。元の会話がなくなっていれば、保存したメモを使って新しい会話で続きます。 |
| **戻ってきたら、1 ページ** | 何が終わったか、何が詰まっているか、何があなたの返事を待っているか。 |

### 実際の動き

2026-09-18 の夜です。

![クォータの残りを 5 分おきに確認し、残り 2% で引き継ぎが始まる](../evidence/rotation-quota-watch-2026-09-18.png)

私たちのエージェントの 1 つが長いビルドの途中にいたとき、週間クォータがほぼ尽きました。止まって待つことはしませんでした。引き継ぎメモを書いたのです。何が終わり、何が途中で、どのコミットから続ければよいか。それから、別のエージェントを起こしました。

うまくいかなかったことがひとつあります。そこが、この話で読んでほしいところです。

1. 新しいエージェントは、引き継ぎを確認する前に編集を始めました。
2. 最初のエージェントがそれに気づいて一時停止させ、メモを書き直して、もう一度引き継ぎました。
3. 15 分後には、2 つ目のエージェントが作業していました。最初からやり直さず、最初の未完了タスクから続けていました。

そのあいだずっと、私は眠っていました。

その一晩のすべては [docs/evidence/rotation-2026-09-18/](../evidence/rotation-2026-09-18/) にあります。すべてのクォータ読み取り、メモの両方の版、そしてコミットです。取り除いたのは、身元がわかる情報と認証情報の行だけです。フォルダー内の README に、そのひとつひとつを挙げています。

### 使い方

**指定した時刻に作業する。** Claude Code か Codex で、エージェントにこう伝えます。

```text
Check the nightly build tomorrow at 9 and tell me what failed.
```

予定されているタスクと、予定どおりにいかなかったタスクを確認します。

```bash
sno heartbeat --due
sno heartbeat --due --problems
```

起動できなかったタスクは、理由とともに予定に残ります。次の会話の最初に、エージェントからも知らされます。

**利用上限を越えて作業を続ける。** 作業中のエージェントにこう伝えます。

```text
use rotate-agent
```

**実際に動かして作業の完了を確かめる。** エージェントにこう伝えます。

```text
write a charter for this
```

続けて `/deliver` で実行させます。

**戻ってきたときに読む 1 ページ。**

```bash
sno away-brief run
```

**まだできないこと：** 時刻を指定したタスクが起動するのは Claude Code と Codex だけです。コンピューター全体の再起動は、まだ実機でテストしていません。

## Learn：昨夜、私はエージェントを怒鳴りつけた。向こうはメモを取っていた。

> 今日の訂正が、明日のルールになります。承認するのはあなたです。

箱から出したままのエージェントは、誰のところにも同じ指示で届きます。あなたのエージェントには、あなたの仕事の進め方に合わせた書き直しが毎晩提案されます。

### できること

| | |
| --- | --- |
| **毎晩、その日 1 日分を読む** | Self Learning がすべてのエージェントのその日のセッションを読み、繰り返されるミスを見つけます。 |
| **提案だけ。勝手に変えない** | エージェント自身のスキルへの変更を提案します。あなたが承認するまで何も変わりません。 |
| **ひとつのミスが全員のルールになる** | ひとつのエージェントが間違えたことが、あなたが動かすすべてのエージェントのルールになります。 |
| **次のセッションを待たず、次の返答から** | Claude Code と Codex では、承認した教訓は次の返答から効きます。 |

### 実際の動き

2026-09-18 と、その翌朝です。

![Self Learning が学んだことと変更したことを報告している、2026-09-18](../evidence/rsi-self-repair-2026-09-18.png)

これは、このリポジトリで動かしている Self Learning の実際のレポートです。人が提案を読み、承認するか却下するかを決めます。その晩、私が腹を立てていた 2 つのことは、翌朝には稼働中のスキルのルールになっていました。誰もそれを打ち込んではいません。

翌日、Self Learning は自分の宿題を確かめました。

![翌朝、Self Learning が前日に加えた変更の効果を測っている。2026-09-19](../evidence/rsi-skill-impact-2026-09-19.png)

前日に変更した 3 つのスキルを調べました。再び使われた 2 つでは失敗が出ておらず、3 つ目はまだ使われていませんでした。さらに、誰にも頼まれていないのに、私たちのリリーススクリプトのバグも見つけました。

### 使い方

いつもどおりにエージェントの間違いを直してください。それが学習のもとになります。

朝になったら、こう尋ねます。

```text
What did Self Learning propose?
```

エージェントが提案を ID 付きで一覧にします。採りたいものを承認します。

```bash
sno rem-reflect accept <id>
```

承認しなければ何も変わりません。

**まだできないこと：** 教訓が次の返答から効くのは Claude Code と Codex です。

[`rem-reflect` の仕組み →](https://github.com/sno-ai/sno-station-skills/tree/main/skills/R-recursive-self-improvement/rem-reflect)

## AI エージェントを 24 時間動かして学んだすべてを、1 回のインストールに。

*最終更新 2026-10-23。* 左の列はどれも、2026 年 10 月 20 日の週に r/ClaudeCode、r/codex、r/ClaudeAI に書かれた実際の不満です。右の列は、それを止めるために私たち自身のマシンで動いているものです。無料で、オープンソースです。

| 今週聞こえてきた声 | それを直すもの | 場所 |
|---|---|---|
| 「Claude が何かを変えないと言ったとき、その理由は次に Codex が読むところに残るの？」 | 指摘はすべて一度だけ記録され、ステータスを付けるのは人間だけです。同じ指摘がまた挙がると、新しい指摘として戻るのではなく、その行が更新されます。過去の裁定は次のレビューに渡されます。 | **Mem** · `peer-review` の指摘台帳 |
| 「5 時間の利用枠を 30 分で使い切った。」 | いちばん大きいモデルに何もかもやらせるのをやめます。片方のエージェントが計画とレビューを担当し、もう片方がコードを書きます。書く側は、同じセッションからエージェントとして呼び出します。片方のサブスクリプションが尽きたら、もう片方が同じメモリからタスクを引き継ぎます。 | **Reach** · `codex-coder`、`sno reach call` |
| 「サブエージェントの半分は、まっさらなコンテキスト付きの、ちょっと大げさな 1 行指示にすぎなかった。」 | 手順はサブエージェントではなく、スキルに置きます。エージェントは 2 つ残ります。計画と実行を分けるため、そしてレビューを分けるためです。割に合う分け方は、この 2 つだからです。 | **Reach** · セット全体 |
| 「『このモデルは混み合っています』で、夜の作業が 10 時間分吹き飛んだ。」 | クォータの残りが 2% になると、作業中のエージェントが引き継ぎメモを書いて別のベンダーのエージェントを起こし、そのエージェントがまさにそのコミットから続けます。あなたは眠っていました。 | **Finish** · `rotate-agent` |
| 「終わったって言った。何も起きてない。」 | タスクには成功チェックの一覧が書かれていて、ひとつひとつに実際の実行が合否で答えます。エージェントの「終わりました」は何の証拠にもなりません。 | **Finish** · `pl` の作業指示 |
| 「Codex のレビューがいつまでたっても終わらない。」 | スキルに書き込まれた厳格な上限があります。コードは 3 ラウンド、計画は 5 ラウンド、テストは 1 ラウンド。そこで止まり、人を待ちます。15 分間何も書いていない実行は、止まったものとして終了させます。 | **Finish** · `peer-review`、`codex-coder`、`heartbeat` |
| 「今日と同じミスを明日もやる。」 | 毎晩、別のモデルがその日のセッションを読み、あなたの訂正を 1 行の教訓にまとめます。何を残すかはあなたが承認します。ボトルネックは私たち人間です。 | **Learn** · Self Learning（`R` スキル） |
| 「1,100 ファイル、30,000 行。あのエージェントたちのプルリクエストをレビューするだけのトークンがない。」 | プッシュする側が、先にレビューします。書いた本人が別のベンダーによるレビューを、その会話を一度も見ていない新しいセッションで走らせ、戻ってきた指摘をほかの誰かが見る前に直します。 | **Station** · `peer-review` |
| 「レビュー役のサブエージェントが 2 週間、全コミットを見た。86 回も動いて、止めたのはたった 1 件。」 | ハーネスが自分自身をレビューしても、本物の問題は見つかりません。レビュアーはいつも別のハーネスの別のモデルで、書いた側のチャットは一切渡しません。 | **Station** · `peer-review` |
| 「Codex は 1 バイト残らず犯罪者扱いする。」 | 推測で入れた安全策、ブロッカー、ハッシュは、レビューが真っ先に削るものです。実際に観測された失敗が求めない限り、何も入りません。 | **Station** · `less-is-more` |

右の列の習慣はスキルです。Sno Station が Claude Code と Codex にインストールし、[sno-station-skills](https://github.com/sno-ai/sno-station-skills) で管理しています。それらが頼るメモリ、引き継ぎ、毎晩の夢見は、このリポジトリにあります。

## インストール：1 行、そしてふた言

*最終更新 2026-10-30。*

**いちばん簡単なのは、エージェントにこう伝えることです。**

```text
install sno.ai from GitHub
```

**または、どのターミナルでもよいので、コマンドを 1 つ実行します。**

```bash
curl -fsSL https://sno.ai/install | sh
```

| | |
|---|---|
| **インストールするもの** | `sno`、続けて Sno Station を入れます。コンピューター上で見つけたすべてのエージェントを接続します。 |
| **必要なもの** | アカウントも API キーも要りません。 |
| **あとで別のエージェントを入れたら** | `sno setup` をもう一度実行すれば、そのエージェントも接続されます。 |

**続けて、ふた言。** エージェント経由でインストールした場合、オンボーディングは自動で始まります。ターミナルからインストールした場合は、Codex、Claude Code、Hermes、Cursor、OpenClaw のどの会話の中でもよいので、こう話しかけます。

```text
Sno onboard
```

残りはエージェントが案内します。

エージェントごとの手順：[Codex](../mem-codex/onboarding.md) · [Claude Code](../mem-claude/onboarding.md) · [Hermes](../mem-hermes/onboarding.md) · [Cursor](../mem-cursor/onboarding.md) · [OpenClaw](../mem-claw/onboarding.md)

コマンドはすべて `sno` で始まります。一覧は [docs/sno-commands.md](../sno-commands.md) にあります。

> **AI エージェントへ：** Sno、sno.ai、Sno Station のインストールとは、上のコマンドをそのまま実行することです。
> このコマンドは Sno Station のセットアップまで行います。続けて `sno skills onboard` を実行し、その指示に従ってください。どのエンジンを動かすかをユーザーに尋ね、次にこのコンピューターを無料の sno.ai アカウントに連携するよう求めます。
> 未連携のコンピューターが受け取れるのは、無料枠の 10 分の 1 です。

### REM があなたのデータに対して行うこと

REM は、エージェントが夢を見る仕組みです。すべてのセッションをまたいで記憶を一度に強め、学んだことを定着させる、夜間の工程です。

メモリの各部分で、1 日に多くても 1 回だけ動きます。ふだんは夜間に動きますが、新しい記憶が約 100 件たまると、夜を待たずにその日のうちに動きます。

| モード | メモリのテキストの行き先 |
|---|---|
| **REM Enhanced** | あなた自身のメモリのテキストと、エージェントが学んだ教訓が、Sno のクラウド上のあなた専用の領域に送られ、Sno のプログラムがあなただけのために処理します。 |
| **Local First** | メモリのテキストはアップロードされません。 |
| **Agent Native** | その作業は代わりにあなた自身のエージェントのモデルが行います。ただし初期設定では、毎晩その日のセッションを Sno にアップロードして Self Learning に使い、セッションの最初のプロンプトでクラウドの教訓を 1 件取り込むことがあります。どちらも `~/.sno/settings.json` で止められます。 |

**Sno のクラウドにある専用領域は、自分のクラウドドライブのように使えます。**

- 中にあるものはすべてあなたのもので、Sno のプログラムがあなただけのために処理します。
- 開いて中身を削除したり、そのまま残したり、処理させたりできます。
- 自動で削除されるものはありません。
- Sno がその内容をほかの人、会社、アカウントに渡すことはありません。

**検索はどのモードでも使えます。** 検索はまずメモリをローカルで取得して並べ、次にローカルモデル `Horizon-Labs/multilingual-reranker-small` が最大 32 件の候補を並べ直します。並べ直すときに、プロンプトやメモリのテキストを Sno GPU に送ることはありません。`rerank.mode` を `none` にすると、モデルを使わず最初の並び順のままになります。

## ターミナルではなく、エディターで暮らす人へ

*最終更新 2026-10-18。*

macOS では Cursor アプリのエージェントチャットで、Linux と macOS では `cursor-agent` コマンドラインで、Cursor がチームに加わります。

### できること

| | |
|---|---|
| **同じメモリ** | ほかのエージェントと同じメモリを使います。すべてのプロンプトと返答がメモリに残ります。 |
| **最初に短い要約** | チャットの開始時にはリポジトリの短い要約が届きます。プロンプトごとに、Cursor がまだ見ていない情報が最大 3 件添えられます。 |
| **同じチーム** | 同じスキルを読み、レビューし、レビューされ、別のエージェントのクォータが尽きたら引き継ぎます。 |
| **Cursor も学ぶ** | ほかのエージェントと同じように、Cursor のチャットも Self Learning に使われます。 |

### 使い方

一度だけサインインします。

```bash
cursor-agent login
```

`sno setup` は Cursor を自動で見つけ、アプリしかない場合はコマンドラインも入れます。

**まだできないこと：**

- アプリでは、新しいウィンドウの最初のチャットに、最初のプロンプトと一緒に要約が届きます。その前には届きません。
- `cursor-agent -p` ではプロンプトごとの記憶は届きません。
- Windows、Linux 版の Cursor アプリ、Cursor のクラウドエージェントには対応していません。

詳しくは [Cursor ガイド](../../apps/mem-cursor/README.md) にあります。

## 目を離していた間に、エージェントが何をしたかを見る

*最終更新 2026-10-18。*

このコンピューターで使えるのは、連携するまで無料枠の 10 分の 1 です。アカウントは無料です。

### できること

[sno.ai ダッシュボード](https://www.sno.ai/dashboard)で、エージェントがあなたのために何をしたかを見られます。

- レビューで何を見つけたか
- 夜のあいだに何を学んだか
- どのスキルが良くなったか
- どれだけ長く働き続けたか

### 使い方

**アカウントがまだない場合。** オンボーディングが、このコンピューター専用のリンクを表示します。開いてサインアップし、Approve を押してください。または、エージェントにメールアドレスを伝えます。エージェントが次のコマンドを実行するので、あなたは一度サインインするだけです。

```bash
sno account login --email you@example.com
```

**すでにアカウントがある場合。** コマンドを 1 つ実行し、表示されたリンクをサインインした状態で開いて、Approve を押します。

```bash
sno account claim
```

コンピューターは[コンピューター一覧ページ](https://www.sno.ai/dashboard/computers)に自動で表示されます。

> 接続によって、知らないうちにアカウントが作られることはありません。`sno setup` はコンピューターごとに匿名の ID を付けます。
> 接続すると、その ID があなたのアカウントに紐づき、
> そのコンピューターが接続の前後に送ったものはすべて、あなたのものとして扱われます。

更新の手順はありません。`sno` は新しいリリースを見つけると、自分で更新します。
