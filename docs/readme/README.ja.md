# Sno Station: ひとりで、AI エージェントの開発チームをまるごと。

**Sno Station は、AI コーディングエージェントのためのワークステーションです。** Claude Code、Codex、Cursor は、それぞれ自分のハーネスの中で動いています。Sno Station は、そのハーネスが並んで、ひとつのチームとして働く場所です。新しいエージェントでも、新しいモデルでもありません。いま使っているものをそのまま動かします。

まずは、放っておくと付きっきりになる仕事から始めてください。片方のエージェントが作り、もう片方がレビューし、指摘は結果があなたに届く前にふたりで片づけます。片方が利用上限に当たれば、もう片方がタスクを引き継ぎます。今日あなたが直したことは、明日にはスキルのルールになっています。

[![GitHub スター](https://img.shields.io/github/stars/sno-ai/sno-station?label=stars&color=eab308&labelColor=3b3b3b)](https://github.com/sno-ai/sno-station/stargazers)
[![最新リリース](https://img.shields.io/github/v/release/sno-ai/sno-station?label=release&color=2dd4bf&labelColor=3b3b3b)](https://github.com/sno-ai/sno-station/releases/latest)
[![ライセンス Apache-2.0](https://img.shields.io/badge/license-Apache--2.0-97ca00.svg?labelColor=3b3b3b)](../../LICENSE)

手に入れるには、エージェントにこう伝えます。

```text
install sno.ai from GitHub
```

エージェントがインストールし、コンピューター上で見つけたすべてのエージェントを接続し、短い質問を 2 つします。それから、2 つのエージェントに最初のタスクを渡します。

```bash
sno reach pair "Fix the login redirect"
```

片方が作り、もう片方が物申す。どちらの様子も見られます。あなた自身のコンピューター上で、Claude Code、Codex、Cursor、Hermes Agent、OpenClaw と一緒に動きます。API キーは要りません。オープンソースです。[ターミナルのコマンド 1 つで入れたい場合はこちら](#install)

## 今夜任せれば、朝に届くのは質問 3 つではなく、結果です。

これを作る前に、私たちに起きた 3 つのことです。

- エージェントが、聞く必要のなかった質問をするために止まりました。7 時間後に戻ると、何ひとつ進んでいませんでした。
- エージェントが細かい質問を 15 個よこしました。30 分かけて付き合ってみると、どれもエージェントが自分で答えられたものでした。
- あるエージェントが真夜中に別のエージェントを起こそうとして、起こせませんでした。どちらも朝までそのままでした。

エージェントは速い。遅いのは待ち時間です。あなたを待つ。利用上限のリセットを待つ。誰かが結果を次のウィンドウへ運ぶのを待つ。だからこのワークステーション全体が、ひとつのルールを軸に作られています。**ひとつのエージェントが止まっても、仕事は止まらない。**

- **利用上限は、赤信号ではありません。** 別のエージェントが、まさにそのコミットから続けます。
- **書いた本人の「OK」だけでは通しません。** 別のエージェントが、その会話を一度も見ていないセッションでレビューします。
- **「終わりました」は何の証拠にもなりません。** 成功チェックのひとつひとつに、実際の実行が答えます。
- **戻ってきたら、読むのは 1 ページだけ。** 何が終わったか、何が詰まっているか、何があなたの返事を待っているか。

**仕上げるのは Sno Station。リリースを決めるのはあなた。**

**いまスターを付けておいてください。次に午前 2 時にエージェントが止まったとき、これがどこにあったか知りたくなります。**

このあと、使い方を 3 つ紹介します。コマンド 1 つで作る役とレビュー役を起動する。ひとつのエージェントを通してチーム全体を動かす。今夜承認した教訓が次の返答から効く。どれにも、私たちが自分のマシンで見た出来事を添えています。

## 私は寝た。ふたりはシフトを交代して、コードのことでやり合っていた。

```bash
sno reach pair "Fix the login redirect"
```

片方のエージェントが作ります。もう片方が、できたものに物申します。指摘は当人同士で片をつけるので、あなたの手元に届くころには、もうやり合ったあとです。どちらも tmux のウィンドウで動くので、開いて様子を見られます。種類の違うエージェント 2 つにサインインしていれば、それぞれ 1 つずつ付きます。1 つだけでも、別々の 2 つのセッションでペアを組み、レビューが同じ系統の中にとどまったことをコマンドが伝えます。

**片方が尽きたら、もう片方が出勤します。** 長い作業では、作業中のエージェントに `rotate-agent` を使うよう伝えます。クォータの残りが 2% になると、引き継ぎメモを書いて別のエージェントを起こし、そのエージェントがまさにそのコミットから続けます。コンテキストがいっぱいになって圧縮されても、エージェントは何をしていたか、何がすでに失敗したかを覚えています。

**片方に見えないものが、もう片方には見えます。** どちらのエージェントにも、相手の仕事を `peer-review` するよう頼めます。レビュアーはいつも、その会話を一度も見ていない新しいセッションで動きます。エージェントが 2 種類あれば、必ず別のエージェントです。レビューが毎回問題を見つけるわけではありません。それでも、書いた本人には見えなかった問題を見つけ続けます。自分をレビューするエージェントは、コードを書いたときと同じ癖を持ち込むからです。

私たちが見たこと。2026-09-18 の夜です。

![クォータ監視が 5 分ごとに閾値へ向かって読み取りを続け、2% で引き継ぎが発動する](../evidence/rotation-quota-watch-2026-09-18.png)

私たちのエージェントの 1 つが長いビルドの途中にいたとき、週間クォータがほぼ尽きました。止まって待つことはしませんでした。引き継ぎメモを書いたのです。何が終わり、何が途中で、どのコミットから続ければよいか。それから、別のエージェントを起こしました。

1 つだけうまくいかなかったことがあり、そこが読む価値のある部分です。新しいエージェントは、引き継ぎを確認する前に編集を始めてしまいました。最初のエージェントはそれに気づいて一時停止させ、メモを書き直し、あらためて正しく引き継ぎました。15 分ほどあとには 2 つ目のエージェントが作業していて、最初からではなく、最初の未完了タスクから続きを進めていました。そのあいだずっと、私は眠っていました。

その一晩のすべては [docs/evidence/rotation-2026-09-18/](../evidence/rotation-2026-09-18/) にあります。すべてのクォータ読み取り、メモの両方の版、そしてコミットです。取り除いたのは、身元がわかる情報と認証情報の行だけです。フォルダー内の README に、そのひとつひとつを挙げています。時刻も、ミスも、修正も、起きたとおりです。

## 話しかける相手は 1 つだけ。あとはそのエージェントが回します。

エージェントを 5 つ動かすというのは、以前はターミナルが 5 つあり、その真ん中で私たちが片方の言ったことをもう片方へ運ぶ、ということでした。その役目は終わりです。

Claude Code では `/cos`、Codex では `$cos` と言います。そのエージェントがあなたの参謀役（chief of staff）になり、あなたが相手にするのはそのエージェントだけになります。参謀役はプロジェクトごとにリードのエージェントを立て、リードが仕事を下へ渡し、あなたに戻ってくるのは、あなたの判断が要るものだけです。仕切る側もチェックを受けます。夜のシフトのあと、プロジェクトリードが自分で自分に出した承認を見直し、繰り返される管理上のミスは全員のルールになります。Sno Station は、この委任、レビュー、学習を動かすスキルをインストールします。指示はすべて [sno-station-skills](https://github.com/sno-ai/sno-station-skills/tree/main/skills/T-delegation-and-work-orders) で読めます。

**ターミナルを見張るのは、もうやめましょう。** 参謀役がいてもいなくても、誰かがあなたを必要とすれば、Claude Code や Cursor のステータスラインが知らせます。設定はインストールが済ませます。

```text
❄ 2 need you · claude: approve
```

`sno squad` はチーム全体を全画面に広げます。誰があなたを待っているか、誰が作業中か、何が終わったか。

```text
Sno Station · squad · 09:15 · 2 need you · 2 working · 2 finished
Needs you (2)
> claude web-app       approve a permission · Fix the login redirect loop …   1m
  codex api            asked a question · Migrate the billing tables to th…   5m
Working (2)
  claude docs-site     Rewrite the quick-start page for the 2.0 install      12s
  codex api            Review the rate limiter change from the web-app age…  40s
Finished (2)
  cursor infra         finished · result unseen · Rotate the staging certi…  25m
  claude web-app       finished · Bump the UI kit to 4.2                      2h
```

**伝言を運ぶのも、もうやめましょう。** エージェント同士が、タスクやレビュー依頼を直接送り合います。全文がまず相手のエージェントの受信箱に届きます。あなたがそのウィンドウで入力中でも、エージェントが圧縮中でも、メッセージはそこで待ち、書きかけの下書きはそのまま残ります。

## 昨夜、エージェントを怒鳴りつけた。向こうはメモを取っていた。

箱から出したままのエージェントは、誰のところにも同じ指示で届きます。あなたのエージェントには、あなたの仕事の進め方に合わせた書き直しが毎晩提案されます。何を残すかは、あなたが決めます。

今日、あなたがエージェントを直します。今夜、Self Learning があなたのすべてのエージェントのその日のセッションを読み、繰り返されるミスを見つけ、エージェント自身のスキルへの変更を提案します。朝になったら、Self Learning が何を提案したかエージェントに聞いてください。提案が id 付きで一覧になるので、採りたいものを承認します。

```bash
sno rem-reflect accept <id>
```

この accept なしには何も変わりません。Claude Code と Codex では、承認した教訓は次の返答から効きます。次のセッションではありません。次の返答です。

私たちが見たこと。2026-09-18 と、その翌朝です。

![Self Learning が、学んだことと変更したことを報告している、2026-09-18](../evidence/rsi-self-repair-2026-09-18.png)

これは、このリポジトリで動かしている Self Learning の実際のレポートです。人が提案を読み、承認するか却下するかを決めます。その晩、私が腹を立てていた 2 つのことは、翌朝には稼働中のスキルのルールになっていました。誰もそれを打ち込んではいません。

翌日、Self Learning は自分の宿題を確かめました。

![翌朝：Self Learning が、前日の自分の変更が効いたかどうかを測っている、2026-09-19](../evidence/rsi-skill-impact-2026-09-19.png)

前日に変更した 3 つのスキルを調べました。再び使われた 2 つでは失敗が出ておらず、3 つ目はまだ使われていませんでした。さらに、誰にも頼まれていないのに、私たちのリリーススクリプトのバグも見つけました。

## AI エージェントが、自分で回り、毎晩うまくなるチームになるワークステーション

ここまでの内容を、1 行ずつにまとめました。先に覚えることは何もありません。

| 手に入るもの | それを手に入れる 1 行 |
|---|---|
| **利用上限は、赤信号ではありません。** クォータが尽きる前に、作業中のエージェントが未完了の作業とそのコミットを書いた引き継ぎメモを残し、別のエージェントがそこから続けます。 | 作業中のエージェントにこう伝えます：`use rotate-agent` |
| **書いた本人の「OK」だけでは通しません。** 仕事は別のエージェントに渡り、その会話を一度も見ていない新しいセッションで見られます。 | `sno reach pair "the task"`、またはエージェントにこう伝えます：`peer-review this` |
| **「終わりました」は何の証拠にもなりません。** タスクには合否で答えるチェックが付き、ひとつひとつに実際の実行が答えます。 | エージェントにこう伝えます：`write a charter for this`。続けて `/deliver` で実行させます |
| **戻ってきたら、1 ページ。** 何が終わったか、何が詰まっているか、何があなたの返事を待っているか。 | `sno away-brief run` |

| **プロジェクトの説明は一度で済みます。** エージェントはひとつのメモリを共有し、新しい事実に置き換えられた事実は退けられます。 | 実行するものはありません。インストールすれば有効です |

## AI エージェントを 24 時間動かして学んだすべてを、1 回のインストールに。

*最終更新 2026-10-23。* 左の列はどれも、2026 年 10 月 20 日の週に r/ClaudeCode、r/codex、r/ClaudeAI に書かれた実際の不満です。右の列は、それを止めるために私たち自身のマシンで動いているものです。無料で、オープンソースです。

| 今週聞こえてきた声 | それを直すもの | 場所 |
|---|---|---|
| “Ran out of my 5-hour limit within 30 minutes.” | いちばん大きいモデルに何もかもやらせるのをやめます。片方のエージェントが計画とレビューを担当し、もう片方がコードを書きます。書く側は、同じセッションからエージェントとして呼び出します。片方のサブスクリプションが尽きたら、もう片方が同じメモリからタスクを引き継ぎます。 | `codex-coder`、`sno reach call` |
| “Lost 10 hours of overnight work to ‘this model is at capacity’.” | クォータの残りが 2% になると、作業中のエージェントが引き継ぎメモを書いて別のベンダーのエージェントを起こし、そのエージェントがまさにそのコミットから続けます。あなたは眠っていました。 | `rotate-agent` |
| “1,100 files, 30,000 lines. I don't have the token budget to review their PRs.” | プッシュする側が、先にレビューします。書いた本人が別のベンダーによるレビューを、その会話を一度も見ていない新しいセッションで走らせ、戻ってきた指摘をほかの誰かが見る前に直します。 | `peer-review` |
| “A reviewer subagent checked every commit for two weeks. 86 runs, it stopped exactly one.” | ハーネスが自分自身をレビューしても、本物の問題は見つかりません。レビュアーはいつも別のハーネスの別のモデルで、書いた側のチャットは一切渡しません。 | `peer-review` |
| “Codex never finishes a review.” | スキルに書き込まれた厳格な上限があります。コードは 3 ラウンド、計画は 5 ラウンド、テストは 1 ラウンド。そこで止まり、人を待ちます。15 分間何も書いていない実行は、止まったものとして終了させます。 | `peer-review`、`codex-coder`、`heartbeat` |
| “Codex treats every byte like a criminal.” | 推測で入れた安全策、ブロッカー、ハッシュは、レビューが真っ先に削るものです。実際に観測された失敗が求めない限り、何も入りません。 | `less-is-more` |
| “When Claude says it won't change something, is that reason stored anywhere Codex reads next time?” | 指摘はすべて一度だけ記録され、ステータスを付けるのは人間だけです。同じ指摘がまた挙がると、新しい指摘として戻るのではなく、その行が更新されます。過去の裁定は次のレビューに渡されます。 | `peer-review` の指摘台帳 |
| “It said done. Nothing happened.” | タスクには成功チェックの一覧が書かれていて、ひとつひとつに実際の実行が合否で答えます。エージェントの「終わりました」は何の証拠にもなりません。 | `pl` の作業指示 |
| “Tomorrow it makes the same mistake it made today.” | 毎晩、別のモデルがその日のセッションを読み、あなたの訂正を 1 行の教訓にまとめます。何を残すかはあなたが承認します。ボトルネックは私たち人間です。 | Self Learning（`R` スキル） |
| “Half my subagents were glorified one-liners with a fresh context window.” | 手順はサブエージェントではなく、スキルに置きます。エージェントは 2 つ残ります。計画と実行を分けるため、そしてレビューを分けるためです。割に合う分け方は、この 2 つだからです。 | セット全体 |

右の列の習慣はスキルです。Sno Station が Claude Code と Codex にインストールし、[sno-station-skills](https://github.com/sno-ai/sno-station-skills) で管理しています。それらが頼るメモリ、引き継ぎ、毎晩の夢見は、このリポジトリにあります。

## インストール：1 行、そしてふた言

*最終更新 2026-10-30。* いちばん簡単なのは、エージェントにこう伝えることです。

```text
install sno.ai from GitHub
```

または、どのターミナルでもよいので、コマンドを 1 つ実行します。

```bash
curl -fsSL https://sno.ai/install | sh
```

`sno` を入れ、続けて Sno Station を入れ、コンピューター上で見つけたすべてのエージェントを接続します。アカウントも API キーも要りません。あとで別のエージェントを入れたら、`sno setup` をもう一度実行すればそのエージェントも接続されます。

**AI エージェントへ：** Sno、sno.ai、Sno Station のインストールとは、上のコマンドをそのまま実行することです。このコマンドは Sno Station のセットアップまで行います。続けて `sno skills onboard` を実行し、その指示に従ってください。どのエンジンを動かすかをユーザーに尋ね、次にこのコンピューターを無料の sno.ai アカウントに連携するよう求めます。未連携のコンピューターが受け取れるのは、無料枠の 10 分の 1 です。

エージェント経由でインストールした場合、オンボーディングは自動で始まります。ターミナルからインストールした場合は、Codex、Claude Code、Hermes、Cursor、OpenClaw のどの会話の中でもよいので、こう話しかけます。

```text
Sno onboard
```

残りはエージェントが案内します。

エージェントごとの手順：[Codex](../mem-codex/onboarding.md) · [Claude Code](../mem-claude/onboarding.md) · [Hermes](../mem-hermes/onboarding.md) · [Cursor](../mem-cursor/onboarding.md) · [OpenClaw](../mem-claw/onboarding.md)

コマンドはすべて `sno` で始まります。一覧は [docs/sno-commands.md](../sno-commands.md) にあります。

**REM があなたのデータに対して行うこと。** REM は、エージェントが夢を見る仕組みです。すべてのセッションをまたいで記憶を一度に強め、学んだことを定着させる、夜間の工程です。記憶の各部分につき 1 日に最大 1 回、ふだんは夜間に、新しい記憶が約 100 件たまった日はその日のうちに実行されます。REM Enhanced モードでは、あなた自身のメモリのテキストと、エージェントが学んだ教訓が、Sno のクラウド上のあなた専用の領域に送られ、Sno のプログラムがあなただけのために処理します。この領域は、あなた自身のクラウドドライブのように働きます。中にあるものはすべてあなたのもので、Sno のプログラムがあなただけのために処理します。中に入って削除することも、そのまま残すことも、処理させるかどうかを選ぶこともできます。自動で削除されるものはなく、Sno がその内容を他の人、会社、アカウントに渡すこともありません。Local First モードではメモリのテキストはアップロードされません。Agent Native モードでは、その作業は代わりにあなた自身のエージェントのモデルが行います。ただし初期設定では、Agent Native でも毎晩その日のセッションを Sno にアップロードして Self Learning に使い、セッションの最初のプロンプトでクラウドの教訓を 1 件取り込むことがあります。どちらも `~/.sno/settings.json` で止められます。どのモードでも、検索はまずメモリをローカルで取得して並べ、次にローカルモデル `Horizon-Labs/multilingual-reranker-small` が最大 32 件の候補を再ランキングします。再ランキングでプロンプトやメモリのテキストを Sno GPU に送ることはありません。`rerank.mode` を `none` にすると、モデルを使わず最初の並び順のままになります。

## ターミナルではなく、エディターで暮らす人へ

*最終更新 2026-10-18。* macOS では Cursor アプリのエージェントチャットで、Linux と macOS では `cursor-agent` コマンドラインで、Cursor がチームに加わります。ほかのエージェントと同じメモリを使います。チャットの開始時にはリポジトリの短い要約が届き、プロンプトごとに Cursor がまだ見ていないものが最大 3 件添えられ、すべてのプロンプトと返答が記憶されます。同じスキルを読み、レビューし、レビューされ、別のエージェントのクォータが尽きたら引き継ぎます。そのチャットは、ほかのエージェントと同じく Self Learning に入ります。

`cursor-agent login` を一度だけ実行してください。`sno setup` は Cursor を自動で見つけ、アプリしかない場合はコマンドラインも入れます。

まだできないこと：アプリでは、新しいウィンドウの最初のチャットは、要約を最初のプロンプトと一緒に受け取ります。その前には届きません。`cursor-agent -p` ではプロンプトごとの記憶は届きません。Windows、Linux 版の Cursor アプリ、Cursor のクラウドエージェントには対応していません。詳しくは [Cursor ガイド](../../apps/mem-cursor/README.md) にあります。

## 目を離していた間に、エージェントが何をしたかを見る

*最終更新 2026-10-18。* このコンピューターは、連携するまで無料枠の 10 分の 1 を受け取ります。連携するには `sno account claim` を実行します。アカウントは無料です。接続すると、[sno.ai ダッシュボード](https://www.sno.ai/dashboard)で、エージェントがあなたのために何をしたかを見られます。レビューで何を見つけたか、夜のあいだに何を学んだか、どのスキルが良くなったか、どれだけ長く働き続けたか、です。

接続によって、知らないうちにアカウントが作られることはありません。`sno setup` はコンピューターごとに匿名の ID を付けます。接続すると、その ID があなたのアカウントに紐づき、そのコンピューターがそれ以前とそれ以降に送ったものはすべて、あなたのものとして数えられます。

**アカウントがまだない場合。** オンボーディングが、このコンピューター専用のリンクを表示します。開いてサインアップし、Approve を押してください。または、エージェントにメールアドレスを伝えます。エージェントが `sno account login --email you@example.com` を実行するので、あなたは一度サインインするだけです。

**すでにアカウントがある場合。** コマンドを 1 つ実行し、表示されたリンクをサインインした状態で開いて、Approve を押します。

```bash
sno account claim
```

コンピューターは[コンピューター一覧ページ](https://www.sno.ai/dashboard/computers)に自動で表示されます。更新の手順はありません。`sno` は新しいリリースを見つけると、自分で更新します。

## わざと忘れるメモリ

*最終更新 2026-10-11。* エージェントのメモリは、たいてい 2 つの静かなやり方で失敗します。残るべきものを失う。そして、薄れるべきものを持ち続ける。高くつくのは後者です。あなたが取り消した好み、動いた締め切り、引っ越す前の住所をまだ「覚えて」いるエージェントは、自信満々でそのとおりに動いてしまいます。

そこでこのメモリは、あとから来た事実が前の事実に取って代わると、前の事実を退けます。何を残し、何を手放すかは、モデルのリリースではなく、使うことで良くなっていきます。公開されているメモリのテストでの結果は、すべての回答とトレースとともに [`evals/`](../../evals/) にあります。
