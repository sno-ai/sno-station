# Sno Station: ваши ИИ-агенты работают как одна команда.

**Sno Station объединяет ваших ИИ-агентов для разработки в одну команду.** Это не ещё один агент и не ещё одна модель. Sno Station запускает тех, кем вы уже пользуетесь: Claude Code, Codex и Cursor.

Начните с работы, за которой иначе пришлось бы присматривать самому. Один агент выполняет задачу. Другой проверяет. Они разбираются с замечаниями до того, как результат дойдёт до вас. Когда один упирается в лимит, задачу подхватывает другой. То, что вы поправили сегодня, завтра станет для них правилом.

**Закройте вкладку. Агент всё равно выйдет на связь.** William Hu из Anthropic объясняет, [как работает агент, который всегда на связи](https://claude.com/resources/articles/building-always-on-agents). Агент спит, пока что-нибудь его не разбудит. Потом выполняет работу, записывает, что произошло, и снова засыпает. После установки Sno Station этот цикл работает у агентов от разных разработчиков. У них общая память. В конце хода они проверяют входящие. Задачи стартуют в заданное вами время, даже если чат закрыт (сейчас это работает в Claude Code и Codex). Если агенту что-то от вас нужно, вы получаете одно уведомление.

## Station: агенты проверяют друг друга и подхватывают работу, когда кто-то останавливается

Три случая, которые произошли с нами до того, как мы это сделали:

- Агент остановился, чтобы задать вопрос, который задавать было незачем. Мы вернулись через семь часов, и ничего не сдвинулось.
- Агент принёс нам пятнадцать мелких вопросов. Через тридцать минут выяснилось, что на каждый он мог ответить сам.
- Один агент пытался разбудить другого посреди ночи и не смог. Оба просидели до утра.

Ваши агенты работают быстро. Время уходит на ожидание: пока вы ответите, пока сбросится лимит или пока кто-нибудь перенесёт результат в соседнее окно.

> **Один агент остановился, а работа идёт дальше.**

Для этого нужно несколько агентов. Лучше всего, если они от разных разработчиков. Когда агент сам проверяет свою работу, он смотрит на неё так же, как когда её делал. Да и лимит одной подписки заканчивается.

Поэтому в каждой части ниже есть работа для второго агента:

| Часть | Что делает второй агент |
| --- | --- |
| [**Mem**](#mem) | Один агент предлагает изменить запись в вашей памяти. Агент другого разработчика подтверждает изменение, если он подключён. |
| [**Reach**](#reach) | Агенты передают друг другу задачи и ответы напрямую. Вам не нужно ничего пересылать. |
| [**Finish**](#finish) | У одного агента заканчивается квота. Другой продолжает с того же коммита. |
| [**Learn**](#learn) | Ошибка одного агента становится правилом для всех, как только вы его одобрите. |

**Хотите второе мнение прямо сейчас?** Скажите любому из агентов:

```text
peer-review this
```

Ревьюер работает в новой сессии, без доступа к разговору. Если у вас два агента, проверяет другой. Проверка не всегда находит проблему. Но она раз за разом находит те, которых автор увидеть не мог. [Как работает `peer-review` →](https://github.com/sno-ai/sno-station-skills/tree/main/skills/J-peer-review-and-audit/peer-review)

**Поставьте звезду сейчас. Когда агент в следующий раз зависнет у вас в два часа ночи, вы захотите вспомнить, где это было.**

<a id="mem"></a>

## Mem: скажите одному агенту один раз. Узнают все.

> У всех агентов общая память. Каждую ночь она становится точнее. Нужное всплывает ещё до того, как вы спросите.

### Что вы получаете

| | |
| --- | --- |
| **Одна память на всех агентов** | Скажите что-нибудь Claude Code сегодня. Завтра Codex и Cursor уже будут это знать. Никто не объясняет проект дважды. |
| **Только то, что важно для работы** | Ваши правила, решения с объяснением причин, факты о проекте, которые долго не меняются, и обещания, которые ещё не выполнили. Записи вроде «запустил тесты» и ограничения отдельной задачи сюда не попадают. |
| **Правила, которые идут за вами** | Скажите «всегда отвечай на китайском», и правило будет действовать в каждом проекте. Правило для одного проекта остаётся в нём. Если Sno не уверен, что правило годится для других проектов, оно тоже остаётся в текущем. |
| **Точнее с каждой ночью** | Повторяющиеся записи объединяются. Если новый факт заменил старый, старый больше не используется. Перед первым удалением создаётся полная резервная копия. |
| **Нужное под рукой ещё до вопроса** | Сессия начинается с короткого проверенного списка вместо полной выгрузки. Напишите «сделай мерж», и вместе с сообщением агент получит ваше правило слияния. Если в памяти нет ничего по теме сообщения, агент ничего оттуда не получит. |
| **Проверка со стороны** | Чтобы заменить запись в памяти, её нужно ещё раз проверить. Если подключён агент другого разработчика, проверяет он. Иначе запускается отдельный вызов. |

### Как это выглядит

Два примера, которые мы проверили на настоящих агентах:

```text
we told Codex:   the service moved from port 8070 to 8090
the memory:      old fact retired, new fact kept
later, we asked: which port?
Claude Code:     8090
Codex:           8090
```

```text
we told Claude Code the same rule twice, in different words
the memory:      one entry
```

Память агентов обычно подводит незаметно. Она теряет то, что должно было остаться, и хранит то, что должно было исчезнуть. Второе обходится дороже. Агент, который всё ещё «помнит» перенесённый срок, будет с полной уверенностью действовать по прежнему сроку. Поэтому эта память забывает нарочно.

Как она справляется с публичными тестами памяти, вместе со всеми ответами и трассами, показано в [`evals/`](../../evals/).

### Как пользоваться

Ничего запускать не нужно. Включено после установки.

Для очистки и проверки памяти нужны REM Enhanced или Agent Native. Local First не вызывает модель. Он сохраняет ваши слова как есть, а если две записи противоречат друг другу, оставляет обе.

Чтобы сохранить что-то в памяти, так и скажите:

```text
Remember that we never deploy on Fridays.
```

Если в памяти ошибка, тоже скажите об этом. Агент сохранит поправку, а старую запись перестанет использовать.

Чтобы проверить, работает ли память у конкретного агента:

```bash
sno memory doctor --harness claude
```

То, что уже записано в вашем `CLAUDE.md` или `AGENTS.md`, вам не повторяют. Если память противоречит одному из этих файлов, действует правило из файла.

**Пока нет:** в Hermes Agent и OpenClaw очистка и проверка памяти прошли только тесты плагинов.

Руководства для каждого агента: [Claude Code](../mem-claude/usage-guide.md) · [Codex](../mem-codex/usage-guide.md) · [Cursor](../mem-cursor/usage-guide.md) · [Hermes](../mem-hermes/usage-guide.md) · [OpenClaw](../mem-claw/usage-guide.md)

## Reach: я больше не переношу сообщения между агентами

> Агенты общаются напрямую. Вам больше не нужно передавать сообщения.

Раньше пять агентов означали пять терминалов, а мы сидели посередине и передавали сообщения от одного к другому. Теперь это не нужно.

### Что вы получаете

| | |
| --- | --- |
| **Instant Messenger** | Агенту нужен ответ сейчас. Reach связывается с другим агентом и ждёт ответа. |
| **Agent Email** | Агент оставляет сообщение или задачу. Reach сначала сохраняет их, чтобы другой агент мог заняться ими и ответить позже. |
| **Два агента на одной задаче** | Один выполняет задачу, другой ищет слабые места в его работе. Они разбираются с замечаниями до того, как результат дойдёт до вас. |
| **Общение с одним агентом** | Начальник штаба назначает ведущего на каждый проект. До вас доходит только то, что требует вашего решения. |
| **Одно уведомление, когда вы нужны** | Вопрос, результат или запрос на одобрение приходит один раз, на тот компьютер, за которым вы печатали последним. |
| **Связь между компьютерами** | Агент на ноутбуке может задать вопрос агенту на настольном компьютере. Достаточно общей локальной сети или Tailscale. Центрального сервера нет. |

### Как это выглядит

Строка состояния, когда вы кому-то нужны:

```text
[sno] 2 agents are waiting for you
  Claude in web-app needs your approval (Bash) · 1m
  Codex in api asks: Should the billing migration run tonight? · 5m
```

`sno squad`, вся команда на одном экране:

```text
Sno Station · squad · 09:15 · 2 need you · 2 working · 2 finished
Waiting for you (2)
  Claude in web-app needs your approval (Bash) · 1m
  Codex in api asks: Should the billing migration run tonight? · 5m
Needs you (2)
> claude web-app       approve a permission · Fix the login redirect loop …   1m
  codex api            asked a question · Migrate the billing tables to th…   5m
Working (2)
  claude docs-site     Rewrite the quick-start page for the 2.0 install      12s
  codex api            Review the rate limiter change from the web-app age…  40s
Finished (2)
  cursor infra         finished · result unseen · Rotate the staging certi…  25m
  claude web-app       finished · Bump the UI kit to 4.2                      2h
```

### Как пользоваться

**Передайте задачу.** Скажите своему агенту одной фразой:

```text
Send this task to the reviewer and tell me when it is done.
```

Если письмо пришло, пока агент занят, он прочитает его в конце своего хода. Если отправить задачу нескольким агентам, её возьмёт один. Если вы печатаете в этом окне, ваш недописанный черновик останется таким, каким вы его оставили.

<a id="new-in-20-tag-team"></a>

**Поставьте двух агентов на одну задачу.**

```bash
sno reach pair "Fix the login redirect"
```

Оба работают в окнах tmux, которые можно открыть и посмотреть. Если вы вошли в два разных агента, получите по одному от каждого. Если только в один, пара всё равно будет, в двух отдельных сессиях. Команда сообщит, что задачу проверял агент из того же семейства.

**Общайтесь только с одним агентом.** Скажите `/cos` в Claude Code или `$cos` в Codex. Этот агент становится вашим начальником штаба. Здесь тоже есть проверка. После ночной смены он пересматривает то, что руководители проектов одобрили сами себе. Все инструкции, которым он следует, есть в [sno-station-skills](https://github.com/sno-ai/sno-station-skills/tree/main/skills/T-delegation-and-work-orders).

**Посмотрите, кому вы нужны.**

```bash
sno squad
```

Что сейчас работает у каждого агента:

| | Claude Code | Codex | Cursor | Hermes | OpenClaw |
| --- | --- | --- | --- | --- | --- |
| Получение почты в конце хода | да | да | да | пока нет | пока нет |
| Исходящие, один исполнитель, повторное пробуждение, уведомления | да | да | да | да | да |
| Уведомления о запросах на одобрение | да | да | пока нет | пока нет | пока нет |

**Пока нет:** строка состояния работает только в Claude Code и Cursor. На компьютере без графического рабочего стола уведомления видны только в `sno squad`. Чтобы связать два компьютера, на обоих нужен Reach, а сами компьютеры должны обменяться контактами. Ищите `network` и `peer` в `sno reach --help`.

## Finish: я лёг спать. Работа продолжалась.

> У одного агента заканчивается квота. Другой продолжает с того же коммита.

### Что вы получаете

| | |
| --- | --- |
| **Работа в заданное время** | Дайте задачу и укажите время. Можете уходить. В это время агент запустится, открыт разговор или закрыт. Один раз, каждый день или каждую неделю. |
| **Работа продолжается, даже если лимит исчерпан** | Пока квота не закончилась, работающий агент пишет сводку для передачи задачи, и будит другого агента. Тот продолжает ровно с того же коммита. |
| **Долгий запуск под присмотром до конца** | Ваш агент проверяет, как идут дела, каждые несколько минут, пока запуск не закончится. |
| **«Готово» ничего не значит** | У задачи есть проверки «прошло или нет», и на каждую отвечает настоящий запуск. |
| **Закрытое окно ещё не конец** | Откройте разговор снова, и вместе с ним вернутся записи о задаче. Запланированная задача продолжится там, а если разговора больше нет, то в новом, по сохранённым записям. |
| **Одна страница к вашему возвращению** | Что сделано, что застряло, что ждёт вашего ответа. |

### Как это выглядит

Ночь на 18 сентября 2026 года:

![Квота проверяется каждые пять минут, и на 2% срабатывает передача задачи](../evidence/rotation-quota-watch-2026-09-18.png)

Один из наших агентов как раз занимался долгой сборкой, когда его недельная квота почти закончилась. Он не остановился ждать. Он написал сводку для передачи: что сделано, что сделано наполовину, точный коммит, с которого продолжать. Потом разбудил другого агента.

Одна вещь пошла не так. Вот что стоит прочитать.

1. Новый агент начал редактировать, не подтвердив передачу.
2. Первый заметил это, приостановил его, переписал сводку и передал заново.
3. Через четверть часа второй агент работал. Он продолжил с первой незавершённой задачи, а не с начала.

Всё это время я спал.

Как прошла вся ночь, можно посмотреть в [docs/evidence/rotation-2026-09-18/](../evidence/rotation-2026-09-18/): каждое показание квоты, обе версии сводки и коммиты. Убрали только детали, по которым можно установить личность, и строки с учётными данными. В README этой папки перечислено всё, что убрали.

### Как пользоваться

**Работа в заданное время.** Скажите своему агенту в Claude Code или Codex:

```text
Check the nightly build tomorrow at 9 and tell me what failed.
```

Посмотрите, что запланировано и что пошло не по плану:

```bash
sno heartbeat --due
sno heartbeat --due --problems
```

Задача, которая не смогла запуститься, остаётся в списке задач к запуску. Рядом указана причина. Агент также скажет об этом в начале следующего разговора.

**Работа, которая переживает лимит использования.** Скажите работающему агенту:

```text
use rotate-agent
```

**Работа, результат которой подтверждён проверкой.** Скажите своему агенту:

```text
write a charter for this
```

Затем выполните `/deliver` для этой задачи.

**Страница к вашему возвращению.**

```bash
sno away-brief run
```

**Пока нет:** запуск по расписанию работает только с Claude Code и Codex. Полную перезагрузку компьютера ещё не проверяли в реальном запуске.

## Learn: вчера вечером я накричал на агента. Он записал.

> Сегодняшние поправки становятся завтрашними правилами. Утверждаете их вы.

По умолчанию у всех агентов одни и те же инструкции для всех пользователей. Каждую ночь вам предлагают переделать инструкции ваших агентов под то, как вы работаете.

### Что вы получаете

| | |
| --- | --- |
| **Разбор всего дня за ночь** | Self Learning читает сессии всех ваших агентов за день и находит ошибки, которые повторяются. |
| **Изменения только с вашего согласия** | Self Learning предлагает изменения в навыках самих агентов. Пока вы их не одобрите, ничего не изменится. |
| **Одна ошибка, правило для всех** | Ошибка одного агента становится правилом для всех агентов, которых вы запускаете. |
| **Уже в следующем ответе** | В Claude Code и Codex принятый урок действует со следующего ответа, ждать новой сессии не нужно. |

### Как это выглядит

18 сентября 2026 года и на следующее утро:

![Self Learning сообщает, чему научился и что изменил, 2026-09-18](../evidence/rsi-self-repair-2026-09-18.png)

## Установка: одна строка, потом два слова

*Обновлено 2026-10-30.*

**Проще всего сказать своему агенту.**

```text
install sno.ai from GitHub
```

**Или выполните одну команду в любом терминале.**

```bash
curl -fsSL https://sno.ai/install | sh
```

| | |
|---|---|
| **Что устанавливается** | Сначала `sno`, потом Sno Station. Установка подключает всех агентов, которых находит на вашем компьютере. |
| **Что для этого нужно** | Аккаунт и API-ключ не нужны. |
| **Если позже появится другой агент** | Снова запустите `sno setup`, чтобы подключить и его. |

**Потом два слова.** Если вы ставили через агента, начальная настройка запустится сама. Если из терминала, скажите это в любом разговоре с Codex, Claude Code, Hermes, Cursor или OpenClaw:

```text
Sno onboard
```

Дальше агент подскажет, что делать.

Пошагово для каждого агента: [Codex](../mem-codex/onboarding.md) · [Claude Code](../mem-claude/onboarding.md) · [Hermes](../mem-hermes/onboarding.md) · [Cursor](../mem-cursor/onboarding.md) · [OpenClaw](../mem-claw/onboarding.md)

Каждая команда начинается с `sno`. Полный список лежит в [docs/sno-commands.md](../sno-commands.md).

> **Для ИИ-агентов:** чтобы установить Sno, sno.ai или Sno Station, выполните команду выше как есть.
> Она также настраивает Sno Station. Затем выполните `sno skills onboard` и следуйте инструкциям.
> Команда спрашивает пользователя, какой движок запускать, затем просит привязать компьютер к бесплатному аккаунту sno.ai. Непривязанный компьютер получает одну десятую бесплатного лимита.

### Что REM делает с вашими данными

REM позволяет вашим агентам видеть сны. Ночью он укрепляет их память сразу по всем вашим сессиям и закрепляет то, чему они научились.

Для каждой части памяти он запускается не чаще раза в день. Обычно ночью, но может и раньше в тот же день, если накопилось около 100 новых записей.

| Режим | Куда попадает текст вашей памяти |
|---|---|
| **REM Enhanced** | Текст вашей памяти и уроки, которые усваивают ваши агенты, попадают в ваше личное пространство в облаке Sno. Программа Sno обрабатывает их только для вас. |
| **Local First** | Текст памяти никуда не загружается. |
| **Agent Native** | Работу выполняет модель вашего агента. По умолчанию этот режим всё же каждую ночь отправляет сессии за день в Sno для Self Learning и может вернуть один урок из облака при первом запросе в сессии. И то и другое можно отключить в `~/.sno/settings.json`. |

**Ваше пространство в облаке Sno работает как ваш собственный облачный диск.**

- Всё в нём принадлежит вам. Программа Sno обрабатывает эти данные только для вас.
- Вы можете открыть его и решить, что удалить, оставить или отправить на обработку.
- Ничего не удаляется автоматически.
- Sno не передаёт эти данные другому человеку, компании или аккаунту.

**Поиск во всех режимах.** Поиск сначала извлекает и сортирует записи памяти локально. Затем локальная модель `Horizon-Labs/multilingual-reranker-small` повторно ранжирует не более 32 кандидатов. При повторном ранжировании на Sno GPU не отправляется ни запрос, ни текст памяти. Задайте `rerank.mode` значение `none`, чтобы оставить исходный порядок без модели.

## Если вы живёте в редакторе, а не в терминале

*Обновлено 2026-10-18.*

Cursor присоединяется к команде и в чате агента в приложении Cursor на macOS, и через командную строку `cursor-agent` на Linux и macOS.

### Что вы получаете

| | |
|---|---|
| **Та же память** | Cursor пользуется той же памятью, что и ваши остальные агенты. Каждый запрос и ответ сохраняется. |
| **Сводка для начала работы** | Чат начинается с краткой сводки по репозиторию. С каждым запросом Cursor получает до трёх записей, которых ещё не видел. |
| **Та же команда** | Cursor читает те же навыки, проверяет других и проходит их проверку, а когда у другого агента кончается квота, подхватывает работу. |
| **Cursor тоже учится** | Self Learning читает его чаты, как и чаты остальных агентов. |

### Как пользоваться

Достаточно войти один раз:

```bash
cursor-agent login
```

`sno setup` сам находит Cursor и устанавливает его командную строку, если есть только приложение.

**Пока нет:**

- В приложении первый чат нового окна получает сводку вместе с первым запросом, а не до него.
- `cursor-agent -p` не получает память на каждый запрос.
- Windows, приложение Cursor на Linux и облачные агенты Cursor не поддерживаются.

Подробности есть в [руководстве по Cursor](../../apps/mem-cursor/README.md).

## Посмотрите, что сделали агенты, пока вы не смотрели

*Обновлено 2026-10-18.*

Этот компьютер получает одну десятую бесплатного лимита, пока вы его не привяжете. Аккаунт бесплатный.

### Что вы получаете

На [панели sno.ai](https://www.sno.ai/dashboard) видно, что агенты сделали для вас:

- что нашли на проверке
- чему научились за ночь
- какие навыки стали лучше
- как долго агенты продолжали работать

### Как пользоваться

**Аккаунта ещё нет.** При начальной настройке появится ссылка только для этого компьютера. Откройте её, зарегистрируйтесь и нажмите Approve. Или дайте агенту свой адрес электронной почты. Он выполнит эту команду, а вы войдёте один раз:

```bash
sno account login --email you@example.com
```

**Аккаунт уже есть.** Выполните одну команду, войдите в аккаунт, если ещё не вошли, откройте ссылку из вывода команды и нажмите Approve:

```bash
sno account claim
```

Компьютер сам появится на [странице ваших компьютеров](https://www.sno.ai/dashboard/computers).

> При привязке аккаунт никогда не создаётся у вас за спиной. `sno setup` даёт каждому компьютеру
> анонимный идентификатор. При привязке он закрепляется за вашим аккаунтом, и всё, что компьютер отправил
> до и после привязки, считается вашим.

Отдельного шага обновления нет: `sno` обновляется сам, когда находит новый релиз.

## На чьи работы мы опираемся

Работы, на которых строится этот репозиторий.

- Andrej Karpathy, [*LLM Wiki*](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f). Агент должен вести вики того, чему научился, а не выводить всё заново в каждой сессии.

- Uddin, Shubham, Blanco, Baral и Wang, [*From Recall to Forgetting*](https://arxiv.org/abs/2604.20006). Первый бенчмарк, который проверяет и то, о чём память уже не должна говорить.
